Abydos Shelves

Shelves at the top answer “what should I read next”. All 951 series follow in the same scroll as the Collection, with a pinned header, category chips, and dividers that follow your sort. Nothing moves to another screen, and every setting you have today keeps working.

One scroll, not two screensShelves and the full library share one grid, so the library is never more than a flick away.
Your settings still rule the CollectionSort, filters, display mode, columns and categories keep their current meaning.
Built from what's already loadedNo new SQL or migrations, and no change to backups. Everything comes from LibraryManga.
Anatomy

One scroll, top to bottom

The phone on the left shows the whole scroll unrolled. The dashed frame is the first screen on a 412 × 915 dp phone. Covers are synthetic.

Scaled about 0.7×. The bottom bar is pinned to the first screen.

  1. 1

    Top bar stays as it is

    The upstream LibraryToolbar keeps the title, the count, search, the filter sheet and the overflow menu. Selection mode swaps it for the selection bar exactly as it does today. The category tabs move down into the Collection header (step 4).

  2. 2

    Continue reading carousel

    Up to 10 series you've started that have unread chapters, ordered by last read. It uses M3E's HorizontalMultiBrowseCarousel, with one large item, one medium and a peeking small one. The large item gets a MomoTalk bubble with the chapter and page, and a resume button that opens the reader straight away.

    The resume button reuses onContinueReadingClicked, the same callback as the existing “continue reading” button.

  3. 3

    Shelves

    New chapters, Not started, and Haruka's own Needs a new source, which only appears when a series sits on a source StaleSources marks unavailable. Each shelf is a horizontal row of up to 15 covers with titles below, ending in a “See all” tile. Empty shelves hide.

    A series appears on at most one shelf, but it always also appears in the Collection.

  4. 4

    Collection header (pinned)

    A stickyHeader labelled “All series · 951” with the current sort as a chip. Tapping the chip opens the existing sort sheet. You don't use categories, so there's no chip row. If categories are ever added, chips appear here automatically and work like today's tabs. When “See all” is tapped on a shelf, a temporary filter chip such as New chapters × appears here.

  5. 5

    Collection grid with sort dividers

    The grid uses your current display mode and column count, unchanged. The mock shows the compact grid. Between groups sit centred MomoTalk-style pills, like the date separators in a chat. What the pills say depends on the sort (table below).

  6. 6

    Fast scroller speaks the dividers

    The existing FastScrollLazyVerticalGrid thumb gains a bubble showing the current section (“This week”, “K”, “Oct 2026”). That's how you cross 951 series quickly.

Behaviour

How it behaves in each situation

Library features you use today

  • Search: as soon as you type, the shelves collapse and the Collection shows the matches, with the existing global-search row at the bottom.
  • Filters and Downloaded-only: apply to both the shelves and the Collection. The filter icon already shows when filters are on.
  • Selection: long-press works everywhere and uses the same selection set and action bar. Range select (onToggleRangeSelection) works in the Collection only, where the order is visible.
  • Pull to refresh: from the top of the scroll. It calls the same onRefresh.
  • Per-category sort and display: choosing a chip calls onChangeCurrentPage, so Mihon's per-category settings keep working.

Edge cases

  • Small or new library: below about 20 series, or when every shelf is empty, the shelves hide and the page is just the Collection.
  • Single category: the chip row hides, matching today's rule for showPageTabs.
  • See all: scrolls to the Collection header and adds a temporary filter chip. It's never saved to your filter preferences, and tapping × clears it.
  • Returning to the tab: the scroll position is remembered with rememberLazyGridState. Re-tapping Library scrolls to the top (shelves), matching onReselect.
  • Turning it off: a Haruka setting (Shelves on/off). Off is today's library, byte for byte.

Where the logic lives

  • :haruka:core: ShelfRules and SortSections as pure functions over a small fork-owned input type (id, started, unread, lastRead, fetchedAt, favoriteAt, title). They have no app dependencies and get unit tests, following the Chapter.toDedupChapter() pattern.
  • app/…/haruka/library/shelves/: the composables and an adapter from LibraryItem. The shelves are computed off the main thread (Dispatchers.Default) and recomputed only when the library list changes.
  • i18n-fork: shelf names, divider labels, the setting label.
  • Patch surface: +1 hook (LibraryContent.kt). The onReselect scroll-to-top may need a second small hook in LibraryTab.kt.

Risks to check

  • Scroll performance: 951 items in one grid is what you have today. The new parts are the carousel and about three horizontal rows at the top. Compare with scripts/haruka/perf/run.sh before and after (reference: under 1.5% jank on Library).
  • API maturity: LazyGridScope.stickyHeader is in the androidx foundation 1.13.0-beta01 in your Gradle cache. It may still be marked @ExperimentalFoundationApi, and I haven't confirmed which version your BOM resolves to. The carousel is in material3 1.5.0-beta, but I haven't checked its parameters.
  • Upstream drift: if Mihon changes LibraryContent's parameters, the hook needs updating. Expect a compile error, not a silent bug.
Delivery

Three phases, each useful on its own

  1. Phase 1

    Frame the Collection

    Pinned “All series” header, sort chip, and sort dividers with the fast-scroller bubble, all on the grid you have now. It already makes 951 series easier to navigate, even before any shelves exist.

  2. Phase 2

    Shelves and carousel

    Continue reading, New chapters and Not started above the Collection, behind the Haruka setting. Run the perf check before and after.

  3. Phase 3

    Polish

    “See all” filter chips, the Needs a new source shelf, and per-shelf hide or reorder in Haruka's settings.

Decisions

CategoriesNot used. No chip row. Chips only appear if categories are added later.
Shelves and categoriesLibrary-wide. Shelves never follow a category.
Collection gridCurrent display mode, unchanged. No title-style change in this work.
FramingF1, one continuous scroll. Losing the sideways swipe between categories is acceptable.
