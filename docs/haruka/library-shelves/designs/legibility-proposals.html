Library legibility pass

Five changes to the library grid and bottom bar, drawn from MomoTalk's bubbles and unread dots, Hoshino's navy and pink, and Material 3 Expressive's bolder containers. Each one targets a specific spot in your screenshot. Contrast ratios are WCAG values computed from the actual HoshinoColorScheme colours.

  • 1Titles on pale or busy covers. The scrim covers only the bottom 33% at 67% black, so the first title line sits on a ~22% scrim. White text on a white cover there is unreadable, and lettering in the art (“Just Want”, “Kon'yaku”) shows through.1.9 : 1
  • 2Unread badge vanishes on pink covers. The secondary pink badge on a pink cover (7th Time Loop, Agents of the Four Seasons) has almost no edge.1.1 : 1
  • 3Selected tab pill is faint. secondaryContainer #6B3550 on the #172438 bar. The selected state relies on the icon fill and label colour.1.7 : 1
  • 4Thin text at 12 sp. Rounded Zen Maru Gothic at Regular weight, with a 4 px blur shadow, smears on dense art.type
Current. Synthetic stress covers, scaled ~0.75×.

// Called from a FORK block in CoverTextOverlay when the Hoshino theme is active.
@Composable
internal fun BoxScope.HoshinoTitleScrim() {
    val navy = MaterialTheme.colorScheme.surfaceContainerLowest
    Box(
        Modifier
            .align(Alignment.BottomCenter)
            .fillMaxWidth()
            .fillMaxHeight(0.52f)
            .background(
                Brush.verticalGradient(
                    0f to Color.Transparent,
                    0.32f to navy.copy(alpha = 0.55f),
                    0.58f to navy.copy(alpha = 0.86f),
                    1f to navy.copy(alpha = 0.94f),
                ),
            ),
    )
}

// Bubble corner: the lower-left is tucked like a MomoTalk message tail.
private val TitleBubbleShape = RoundedCornerShape(12.dp, 12.dp, 12.dp, 4.dp)

@Composable
internal fun BoxScope.HoshinoTitleBubble(title: String) {
    Surface(
        modifier = Modifier
            .align(Alignment.BottomCenter)
            .fillMaxWidth()
            .padding(6.dp),
        shape = TitleBubbleShape,
        color = MaterialTheme.colorScheme.surfaceContainerHigh.copy(alpha = 0.93f),
        shadowElevation = 2.dp,
    ) {
        Text(
            text = haruka.title.rememberDisplayTitle(title),
            modifier = Modifier.padding(horizontal = 8.dp, vertical = 5.dp),
            style = MaterialTheme.typography.labelMedium,
            maxLines = 2,
            overflow = TextOverflow.Ellipsis,
        )
    }
}

Recommendation

A + D + E, with B as an option

  1. Try C now (Comfortable grid in Display settings). If you prefer titles below covers, the overlay changes matter much less.
  2. Ship A, D and E as Hoshino-only. They fix all four problems with three thin FORK hooks. Other themes and the STANDARD look stay exactly as upstream, which keeps patch-surface.sh small.
  3. Add B as a choice (plate or bubble) once A is in. It's the most MomoTalk option, but it covers more art, so it's better as a preference than a default. The preference label needs a string in i18n-fork.
  4. Add one shared LocalHoshinoAccents-style flag in HarukaExpressiveTheme rather than checking AppTheme in each hook.

The mockups use synthetic covers chosen as worst cases (white, pink, yellow, and lettering where the title lands), not your library. Ratios assume the dark Hoshino scheme. The light scheme needs its own pass for A and D.

Going further

Three radical layouts

A–E tidy up a wall of 951 covers. These three change what the Library tab is for. The cover sits next to the title or above it, never behind it, so the legibility problem doesn't arise. Each one is built from Material 3 Expressive components that are already in your material3 1.5.0-beta dependency, and each uses only fields LibraryManga already carries (unreadCount, latestUpload, lastRead, hasStarted).

R1 · MomoTalk

Inbox

MomoTalkM3E button group

Each series is a conversation: a rounded cover as the avatar, the full title over two lines, and a line saying what changed (“3 new chapters”). Rows are sorted by newest chapter, with a coral unread count on the right. All / Unread / Reading sit in a connected button group.

  • Gains: the title gets the whole row width. The tab answers “what's new” at a glance, as MomoTalk does.
  • Loses: cover browsing. Covers become 46 dp avatars.
  • Data gap: the latest chapter's name isn't in LibraryManga. Counts and times work as-is. Chapter names would need an extra query.
Recommended R2 · Hoshino

Abydos shelves

HoshinoM3E carousel

The Library becomes a home screen. At the top is a Continue reading carousel (HorizontalMultiBrowseCarousel, the large-medium-small strip), with a MomoTalk bubble on the hero cover. Below are shelves by reading state: New chapters, Reading, Not started. Titles sit under each cover. “See all” opens today's grid, filtered to that shelf.

  • Gains: “what do I read next” fits on one screen, and the 951-cover wall is now one tap away instead of the first thing you see.
  • Loses: categories lose their tabs. They could become extra shelves, or stay in “See all”.
  • Cost: the most new UI of the three, with nested lazy rows. Run scripts/haruka/perf/run.sh before and after.
R3 · M3E

Thumb-first

M3E floating toolbarShort nav bar

The top app bar goes. “Library 951” becomes a large header that scrolls away, and category chips replace the tabs. Search, filter and sort move to a HorizontalFloatingToolbar above a ShortNavigationBar. The grid becomes two columns with titles below and MomoTalk dots.

  • Gains: covers about 50% wider, titles that never overlap art, and every control within thumb reach on a tall phone.
  • Loses: density, about 4–6 covers per screen instead of 9. The toolbar has to hide on scroll.
  • Combines with R1 or R2. It only changes the controls around the content, not the content itself.

How a radical layout lands in the fork

  1. Add a fork preference, libraryLayout (Grid / Shelves / Inbox), in harukaPreferences. Grid is the default and leaves upstream untouched, so the STANDARD path stays identical.
  2. Add one FORK hook where LibraryContent picks the pager. It hands the already filtered and sorted items to haruka.library.ShelvesLayout or InboxLayout. No new SQL, no migrations, and backups are unaffected (hard rules 2 and 3).
  3. Shelves are plain filters over LibraryManga: unreadCount > 0 sorted by latestUpload, hasStarted sorted by lastRead, and the rest. Shelf names and the preference labels go in i18n-fork.
  4. Ship A + D + E first. Those changes make the grid behind “See all” readable too, so the work isn't wasted if you go radical later.
